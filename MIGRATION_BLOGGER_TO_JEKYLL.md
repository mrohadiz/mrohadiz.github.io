2. For `MIGRATE; PRESERVE URL`, set Jekyll front matter `permalink` exactly to the **legacy path** shown below (for example, `/2025/12/example.html`).
3. For `MERGE + 301`, do not publish a second near-duplicate. Map the old path to the indicated garden URL with a server/edge `301` redirect.
4. For `REVIEW THEN MIGRATE`, decide whether the article remains useful without its news context; migrate only if it adds durable knowledge.
5. For `ARCHIVE; DO NOT MIGRATE`, retain a private/offline source backup and redirect the old URL to the closest relevant hub only if one genuinely exists; otherwise return a true `404` after the transition period.
6. Do not detach the Blogger custom domain or unpublish the source blog until all target pages, canonical URLs, redirects, sitemap, and Search Console checks are validated.
